Local verification of the redesigned deploy/smoke_test.py (Issue #99), branch
feature/smoke-test-d2 (PR #100), commit 51bc0bb391d2543d532c6d91be752e6e9151c1a8
(same commit as origin/sprint-1-staging; the smoke script is an uncommitted
working-tree change built into each test image below, until this round's
commit).

This supersedes the previous version of this file (same filename, earlier
commit): the script was redesigned after review so that the default mode
(SMOKE_D2 unset) is byte-for-byte the Sprint-1-only script at origin/main,
and all Sprint 2/3 coverage moved behind an explicit SMOKE_D2=1 opt-in, with
two named soft preconditions (a second account; the Lab 7 fixture goal) that
SKIP rather than FAIL when absent. The earlier version ran the Sprint 2/3
checks automatically whenever SMOKE_EMAIL/SMOKE_PASSWORD were set, which
would have FAILed on a clean/rolled-back database with no Sprint 2/3 fixture
data yet - a design bug, fixed here, not worked around.

- Dedicated Postgres: `docker run postgres:16-alpine`, container smoke-d2-pg,
  port 55440 (not the project's usual dev DB on 5434, not the F-06 worktree's
  test DB on 55432).

  (the real multi-stage Dockerfile - same image shape as the real deploy).
- Migrations + seed: `npx prisma migrate deploy && npm run db:seed` run once
  inside that image against the dedicated Postgres (SEED_PASSWORD_* were
  throwaway local-only values, never printed here).
- App container: `docker run -p 18090:3000 ... habit-tracker-smoke-d2`, with
  NODE_ENV=development (image default is NODE_ENV=production). One
  deliberate, disclosed difference from production: backend/src/lib/
  session.ts's session cookie is `secure` only when NODE_ENV=production, and
  express-session's own documented behaviour is "If secure is set, and you
  access your site over HTTP, the cookie will not be set" - confirmed by
  testing both ways locally. No route handler branches on NODE_ENV, so this
  does not affect what any check verifies; it was only needed to get a
  session cookie at all over plain local HTTP. The real Cloud Run service is
  HTTPS, unaffected.
- Local python3 is 3.8 (no `zoneinfo`, stdlib since 3.9); used
  /Library/Frameworks/Python.framework/Versions/3.9/bin/python3 (3.9.6) for
  every run below. The deploy workflow's own Python is 3.14
  (actions/setup-python, .github/workflows/deploy.yml) - a local machine
  difference, not a script compatibility issue.
